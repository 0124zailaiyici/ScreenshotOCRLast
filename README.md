# ScreenshotOCR

Windows 截图工具，支持截图后三选一操作：钉住到屏幕、OCR 识别文字、复制图片。常驻系统托盘，`Alt+X` 全局热键触发。

## 1. 项目背景

本项目旨在提供一个轻量级、无外部框架依赖的截图工具，支持以下核心流程：

- **全局触发**：通过 `Alt+X` 快速进入截图模式。
- **选区操作**：支持鼠标拖拽选择区域，并提供 \[钉住 | 识字 | 复制] 三合一工具栏。
- **高级 OCR 与翻译**：
  - **OCR**：内置**两个**离线引擎，托盘菜单「识别引擎」里随时切换 —— **RapidOCR**（默认，PaddleOCR 模型，中文准确率高，模型随程序打包、无需额外安装）与 **Tesseract**（需自行安装 Tesseract-OCR 5.x）。请求的引擎不可用时会自动降级到另一个，并在状态栏说明。
  - **翻译**：支持多引擎翻译（默认阿里云），具备**语言自动检测**、**目标语言切换**及**本地历史记录**功能。
- **用户主控复制**：废弃自动复制。
- **系统集成**：常驻系统托盘，支持配置持久化。

## 2. 界面

界面为**纯 Tkinter 自绘**，不依赖任何 GUI 框架（也没有 Electron/Qt 的体积）。

- **主题**：深色 / 浅色自动跟随系统，强调色取自系统 AccentColor（按钮、选中态、光标都用它派生）。
- **识字窗口**：顶部操作栏（复制 / 重新识别 / 原文·中文·EN）+ 圆角文本卡片 + 底部状态栏（字数、识别耗时、当前视图、当前引擎）。
- **截图工具栏**：圆角浮窗，三个操作之间有分隔线，鼠标悬停有反馈。
- **钉住窗口**：拖动移动、滚轮缩放，**右键弹出菜单**（复制图片 / 识别文字… / 取消钉住），`Esc` 直接关闭。菜单是自绘的圆角深色卡片 —— 用 `tk.Menu` 的话它在 Windows 上不受系统深色主题控制，会弹出一个浅灰方块。
- **字体**：`Microsoft YaHei UI` —— 同时含拉丁与中日韩字形。用 `Segoe UI` 的话中文只能靠逐字回退，中英文混排会字重不一致。
- **DPI 感知**：字号用「点」自动缩放，间距按显示器缩放系数换算，150% 缩放下观感与 100% 一致。

### OCR 引擎对比（同一张真实难图，相似度按去空白字符计）

| | RapidOCR（默认） | Tesseract |
|---|---|---|
| 中文 | **正确** | 有错字（`渲染`→`泻染`、`自检`→`目检`） |
| 相似度 | **100.0%** | 96.9% |
| 速度 | 约 1.2s | 约 0.5s |
| 需要额外安装 | 否（模型已打包） | 是（Tesseract-OCR 5.x） |
| 代价 | EXE +81MB | — |

### 资源占用（实测）

打包后的 EXE 空转（未使用翻译、未用过 RapidOCR）时：

| 指标 | 数值 |
|------|------|
| 工作集 | 约 58 MB |
| 私有内存 | 约 34 MB |
| 线程数 | 12 |
| **空闲 CPU** | **0.000%** |

OCR 引擎 `tesseract.exe` 是每次识别时 spawn 的子进程、用完即退，其内存不计入本进程。
翻译所用的 `translators` 库重达 48MB，已改为**首次点击翻译时**才加载，因此常驻期间不占用。
RapidOCR 的 onnxruntime 与 numpy 同样延迟加载 —— 只启动不识别时不会付出这份内存。

## 2. 功能详细说明

### 2.1 OCR 识别与翻译

- **识别流程**：截图 -> 点击“识字” -> 弹出 OCR 窗口。
- **翻译增强**：
  - 支持 `zh`, `en`目标语言。
  - 自动检测源语言。
  - 翻译失败自动重试或弹出错误提示。
  - 翻译历史记录保存在 `translation_history.json`。

### 2.2 复制管理

- **手动触发**：OCR 识别后，用户需点击按钮才执行复制。
- **选择复制**：支持用鼠标选中特定行/词进行复制。


## 3. 安装与运行

### 环境要求

- Windows 10/11
- Python 3.10+（**仅源码运行需要**；用装好的 EXE 不需要装 Python）
- **Tesseract-OCR 5.x**（**可选**）：
  - **默认引擎 RapidOCR 不需要它** —— 模型已随程序打包，装上就能用中文识别。
  - 只有想用 Tesseract 引擎（托盘菜单里可切）时才需要：[UB-Mannheim/tesseract](https://github.com/UB-Mannheim/tesseract/wiki)，安装时勾选 **"Additional language data (download)"** 里的 **"Chinese"**。
  - 程序会自动在 `C:\Program Files\Tesseract-OCR` 搜索，装在别处时会在提示里让你手动指定 `tesseract.exe` 路径。

### 安装（推荐，装完从开始菜单/桌面打开）

```bash
python build_exe.py     # 先打包
python install.py       # 再安装
```

装完之后：

- **开始菜单**搜索「截图」或「ScreenshotOCR」即可打开
- **桌面**有快捷方式
- 「设置 → 应用 → 已安装的应用」里有卸载入口；也可以直接运行安装目录下的 `卸载.cmd`

安装位置是 `%LOCALAPPDATA%\Programs\ScreenshotOCR`，**全程不需要管理员权限**，也不会往 `Program Files` 写东西。

几个刻意的取舍：

- **不设开机自启**。它是托盘常驻工具，重启后需要自己打开一次 `Alt+X` 才生效 —— 要不要自启由你决定，安装脚本不替你做。
- **卸载不动用户数据**：配置、钉住图片、翻译历史都在 `%APPDATA%\ScreenshotOCR`，卸载后仍在，重装后设置还在。
- **不打包成 Inno Setup / NSIS 安装程序**：这是单文件绿色 exe，"安装"本质上就是"放个固定位置 + 建快捷方式 + 留个卸载入口"，为它引入一整套安装框架并不划算。

### 直接从源码运行

1. **安装依赖**：
   ```bash
   pip install -r requirements.txt
   ```
2. **运行程序**：
   ```bash
   python main.py
   ```
3. **运行测试**：
   ```bash
   pytest test_app.py test_integration.py test_pin_logic.py
   ```
   另可运行环境自检（失败返回非零退出码）：
   ```bash
   python verify_app.py
   ```

### 打包为 EXE

```bash
python build_exe.py
```

打包完成后在 `dist/` 目录下得到 `ScreenshotOCR.exe`，也可以直接双击运行（只是没有快捷方式）。

打包脚本会在结束后**自检产物**：读回 exe、核对必需模块与**数据文件**（RapidOCR 的三个 ONNX 模型）是否齐全、该排除的（pandas 等）是否确实没进去，不合格就以非零码退出。这样"看起来打包成功、用起来缺功能"的情况不会悄悄溜过去 —— 这道检查真的拦下过一次漏打的模型文件。

图标由 `python make_icon.py` 生成到 `assets/app.ico`（设计与托盘图标一致），打包时通过 `--icon` 嵌入。

**钉住的图现在能复制、也能重新识字了**

- **\[Feature]** 钉住窗口支持**右键菜单**：**复制图片**（原始分辨率）、**识别文字…**（拿原图重新识别并打开识字窗口）、**取消钉住**。

  - **「识别文字」把识字窗口挂在钉住窗口的父窗口下**，而不是钉住窗口本身 —— 否则关掉钉住会把识字窗口一起销毁。

  - **不用 `tk.Menu`**：它在 Windows 上不受系统深色主题控制，会弹出一个浅灰方块，是这个全自绘界面里唯一不搭的东西。
  - 关闭路径有四条（点中某项 / 点菜单外 / `Esc` / 焦点离开）。前两条靠 `grab_set()` —— 应用内的点击会被重定向到菜单窗口，即便点在别的窗口上坐标也落在矩形外，**所以命中判定必须能识别出"点在外面"**；第四条靠 `focus_force()` 之后的 `<FocusOut>` 兜底，因为本地 grab 管不到应用外的点击。
  - **菜单打开时要暂停钉住窗口的 2 秒置顶定时器**，否则它会把刚弹出来的菜单盖住。
- **\[Fix]** 关闭钉住窗口时会先收掉正开着的菜单 —— 菜单持有 grab，直接销毁父窗口会留下一个孤儿 Toplevel。
- **\[Test]** 用例数 75 → 88。新加的回归防护**都验证过"把修复改回去就会失败"**，过程中发现两条第一版是**恒真**的：① 直接调 `_on_context_menu` 测不出"右键绑定被改回关闭"，必须真的 `event_generate("<Button-3>")`；② 单独测"点分隔线不执行任何东西"也是恒真的，因为命中判定会跳过分隔线返回 -1、那条有 bug 的代码根本走不到。

### [v1.4.0] - 2026-10-15

**换了识别引擎：中文终于不出错字了**

- **\[Feature]** **内置 RapidOCR，并保留 Tesseract，可在托盘菜单里随时切换**（默认 RapidOCR）。同一张真实难图上，RapidOCR 相似度 **100.0%**、Tesseract **96.9%**；差别全在中文上 —— Tesseract 把 `渲染` 认成 `泻染`、`自检` 认成 `目检`、`0 FAIL` 认成 `/0 FAILL`，RapidOCR 全对。代价是 **EXE 从 36MB 涨到 117MB**（onnxruntime + numpy + 三个 ONNX 模型），换来的是**不需要用户额外安装任何东西**。
- **\[Feature]** 请求的引擎不可用时**自动降级**到另一个，并在状态栏说明原因，而不是直接报错。识字窗口的状态栏现在会显示当前用的是哪个引擎。
- **\[Fix]** **RapidOCR 会吞掉拉丁词之间的空格**（`pytest 60 passed` → `pytest60passed`）。靠 `return_word_box=True` 拿到的逐字符框把空格补回来；但**汉字之间绝不插**（否则会得到 `真 实 渲 染` 这种废文本），单位也不拆（`36.16MB` 不能被拆成 `M B`）。
- **\[Fix]** **`is_available()` 不能靠 `import` 判断**。托盘菜单在**构建菜单时**就会问一次引擎可用性（要标注「未安装」），而 `import rapidocr_onnxruntime` 会连带加载 onnxruntime + numpy —— 于是"延迟加载"被彻底绕过：只是启动程序、什么都没做，工作集就从 50MB 涨到 **86MB**、线程 9 → **27**。改用 `importlib.util.find_spec`。
- **\[Fix]** **numpy 一装上，`pytesseract` 就会在启动时加载它**（`pytesseract.py:35` 有一句 `from numpy import ndarray`，包在 `try/except` 里；以前 numpy 没装所以静默失败、零代价）。而 numpy 现在是 onnxruntime 的硬依赖、必然装着，于是每次启动都会拉起 **OpenBLAS 线程池** —— 实测私有内存 **516MB**。修法是在 `import pytesseract` **之前**把 `OPENBLAS_NUM_THREADS` 等环境变量设为 `1`（顺序错了就等于没修）。限制成单线程**不会拖慢识别**（推理是 onnxruntime 自己的线程池在做），实测 1.24s → 1.17s。综合后空闲占用：**58MB / 34MB 私有 / 12 线程**（改造前是 50MB / 9 线程）。
- **\[Fix]** 打包自检新增**数据文件**校验。第一次把 RapidOCR 打进去时 `--collect-data` 漏了三个 ONNX 模型，自检直接报「数据文件没打进包」并退出 —— 这正是这道检查存在的意义。

### [v1.3.3] - 2026-10-14

**识字更准了，窗口也不再「跑远」**

三个用户反馈的问题，其中两个是真 bug：

- **\[Fix]** **选区边框被拍进了识别输入** —— 覆盖层抓图时窗口还显示着，而选区边框（3px 白框 + 1px 虚线强调框）正好画在选区边缘上。实测**贴着文字选时识别率从 90% 崩到 4.3%**（留白 6px 以上则无影响，所以只在"选得紧"时发作，极难反推）。改成从覆盖层**早就拍好的**干净全屏图里裁剪，不再重新抓屏。附带好处：不受"抓图期间屏幕变化"影响，还省掉一次全屏抓取。
- **\[Fix]** **`round_rect` 画的圆角是错的**（影响整个 UI）。原来用 `create_polygon(smooth=True)`，而 Tk 的 `smooth` 是 B 样条、曲线不经过给定点，圆角量由点间距决定而不是由传入的半径决定 —— 实测请求半径 4/8/12/20 时左上角挖掉的像素数是 35/36/38/47（几乎不变），右下角是 0/1/3/12（基本是直角）。改成显式采样圆弧点，圆角深度随半径正常增长且四角一致。`RoundedCard`（文本卡片、截图工具栏）与细滚动条滑块都受益。
- **\[Fix]** **无边框窗口的位置会丢失** —— `overrideredirect(True)` 之后，映射前设置的窗口位置会被丢弃，窗口永远出现在屏幕左上角。改成 `withdraw` → 一次性设好尺寸+位置 → `deiconify`。
- **\[Fix]** 操作栏宽度改用**实测值**而不是写死的常数。操作栏设了 `pack_propagate(False)` 后 `winfo_reqwidth()` 恒为 1，给少了会把分段控件挤小（实测 245 → 180，文字被裁）。
- **\[Change]** **识字窗口去掉原生标题栏**（原来那一条写着「OCR 识别」）。改成圆角无边框卡片，顶部操作栏兼任拖动条，最右新增 ✕ 关闭按钮 —— 去掉标题栏后窗口既不能拖也不能关，这两个一起补上了。窗口还会强制抢一次键盘焦点，否则 Text 里的 Ctrl+C 与拖选会失效。
- **\[Change]** **窗口改为贴在选区正下方展开**（原来是摆在选区右侧）。窗口最宽 900 物理像素，一靠屏幕右边就整块翻到选区左侧 —— 右边缘贴着选区、左边缘却甩出去近千像素，看起来就是"跑到别处去了"。现在左边缘与选区对齐、向下展开，下方放不下才翻到上方，横向只收拢不翻转。

### [v1.3.2] - 2026-10-14

**修掉「翻译偶发失败」：`translators` 在导入期发网络请求**

起因是 `verify_app.py` 的自检**时好时坏**（连跑 25 次挂 2 次）。查下去发现不是自检的问题：

- **\[Fix]** `import translators` **在导入期就会发 HTTP 请求**探测所在地区 —— 它的模块体里直接写了 `tss = TranslatorsServer()`（`server.py:6205`），构造函数调用 `get_region_of_server()`（`server.py:5896`），后者请求 `geolocation.onetrust.com`、失败再退到 `httpbin.org`（`server.py:364`）。探测失败会抛 `TranslatorError`，**整个 import 直接失败** —— 用户点「翻译」看到的就是一个跟 httpbin.org 有关的报错。而且那两次 `requests.get` **没设 timeout**，网络不通时还可能挂很久
- **\[Fix]** 修法是 `server.py:344` 自己留的逃生口：只要 `translators_default_region` 有值，`get_region_of_server` 就在第一行直接返回、不发任何请求。现在 `translator._translators()` 在 `import translators` **之前**先钉住地区（默认 `CN`，用 `setdefault` 所以不覆盖用户自己设的值；非中国大陆用户可设 `EN`）

### [v1.3.1] - 2026-10-13

**对抗式复核后的修复：3 条 MAJOR + 7 条 MINOR**

复核发现的问题不是"代码写错"，而是**声明的保证与实际不符** —— 三处都是"说好了要防，其实没防住"。

- **\[Fix]** 脏配置能让「钉住」静默失败：`_sanitize` 对 `pinned_items` 只校验了容器类型（是 list 就放行），**不校验元素**。列表里混进一个字符串就抛 `AttributeError`，被 `main._do_screenshot` 的 except 吞掉 —— 用户看到的是"点了钉住，什么都没发生，也没有任何提示"。现在在**加载 / 写入 / 读取**三个边界都做逐元素清洗；`pos` 形状不对时只丢这个字段，不丢整条钉住记录
- **\[Fix]** 测试隔离名不副实：`translator` 在导入期就绑定了 `config_manager` 并构造了单例，`Translator.__init__` 当场把 `config_dir` 算成了 `history_file`。测试模块在收集期就导入它，那时隔离夹具还没运行 —— 于是从"隔离"上下文写翻译历史会**真的落进用户真实配置目录**。现在连单例上已算好的 `history_file` 一起重定向
